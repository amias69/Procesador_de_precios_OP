# Manifiesto del Proyecto

## Introducción

Todo proyecto de software nace para resolver un problema.

Este no es la excepción.

Observatorio de Precios fue concebido con un propósito muy concreto: transformar un proceso manual, repetitivo y propenso a errores en una herramienta simple, rápida y confiable.

Desde el inicio, cada decisión técnica fue tomada pensando en un único objetivo: respetar el tiempo de las personas que utilizarán esta aplicación.

La tecnología utilizada es importante, pero nunca fue el punto de partida. El verdadero valor del proyecto reside en la capacidad de convertir una tarea que puede tomar horas en un proceso que se completa en cuestión de segundos.

---

## Objetivo

Desarrollar una herramienta libre, mantenible y fácil de utilizar que permita generar archivos compatibles con el Observatorio de Precios de DIGEMID de forma rápida, confiable y reproducible.

La aplicación busca eliminar el trabajo repetitivo sin reemplazar el criterio profesional del usuario.

La responsabilidad de analizar la información siempre seguirá perteneciendo a las personas; el trabajo de la aplicación consiste en automatizar todo aquello que pueda automatizarse de manera segura.

---

## Nuestra filosofía

Creemos que un buen software no es aquel que incorpora la mayor cantidad de funciones.

Es aquel que resuelve correctamente el problema para el cual fue creado.

Cada nueva característica debe justificar su existencia.

Cada línea de código debe aportar valor.

Cada dependencia incorporada debe resolver un problema real.

---

## Principios de desarrollo

Cada decisión tomada durante el desarrollo de este proyecto busca respetar los siguientes principios:

### Simplicidad

La solución más sencilla que resuelva correctamente el problema será siempre la primera opción.

Se evita incorporar complejidad innecesaria, dependencias prescindibles o funcionalidades que no aporten un beneficio real al usuario.

La simplicidad no representa una limitación; representa una decisión de diseño.

---

### Utilidad

Cada característica debe responder a una necesidad concreta.

El objetivo no es construir la aplicación con más funciones, sino la herramienta más útil para quienes la utilizan.

---

### Mantenibilidad

El proyecto debe poder comprenderse, mantenerse y evolucionar con facilidad.

La claridad del código, la organización de la arquitectura y la documentación forman parte del producto tanto como la propia aplicación.

---

### Transparencia

Las decisiones importantes del proyecto deben quedar documentadas.

La documentación no es un complemento del desarrollo; forma parte del desarrollo.

---

### Comunidad

Este proyecto se distribuye como software libre con la intención de que pueda estudiarse, mejorarse y adaptarse a nuevas necesidades.

Las mejoras realizadas sobre la aplicación representan una oportunidad para fortalecer el proyecto y beneficiar a quienes lo utilicen en el futuro.

---

## Alcance

Observatorio de Precios tiene un objetivo claramente definido.

No pretende convertirse en un sistema integral de gestión farmacéutica ni incorporar funcionalidades ajenas a su propósito.

Su responsabilidad comienza con la preparación de la información y concluye con la generación de un archivo compatible con el Observatorio de Precios.

Mantener este enfoque permite conservar una aplicación simple, estable y fácil de utilizar.

---

## Compromiso

Este proyecto es el resultado de una convicción sencilla:

La tecnología debe reducir el tiempo que las personas dedican a tareas repetitivas para que puedan concentrarse en aquello que realmente requiere su criterio, conocimiento y experiencia.

Cada mejora futura deberá respetar ese propósito.

Mientras esa idea permanezca intacta, el proyecto seguirá avanzando en la dirección correcta.
